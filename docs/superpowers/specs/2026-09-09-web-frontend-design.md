# 웹 프론트엔드 설계

**대상 레포:** `jihxn-kim/quiz-app-web` (public, 현재 비어 있음)
**백엔드:** `jihxn-kim/quiz-app` — 게임 API 완성됨. 이 스펙은 백엔드 변경도 일부 포함한다.
**배포:** Vercel (개인 스코프 `jihuns-projects-67e3e831`) ↔ Railway (`https://quiz-app-production-6e37.up.railway.app`)

## 무엇을 만드는가

초대된 친구들끼리 한 질문에 각자 답을 적고, **전원이 제출했을 때만** 서로의 답이 열리는 게임의 웹 클라이언트.

핵심은 흐름이 아니라 **열리는 순간**이다. 답이 한꺼번에 공개되는 그 순간이 이 게임의 전부이고, 그게 밋밋하면 앱이 밋밋하다. 설계의 상당 부분이 그 순간을 위해 있다.

## 범위

**포함**
- 방 만들기 / 초대 링크로 참가
- 대기실 (참가자 목록, 링크 공유)
- 라운드: 질문 표시, 답변 작성, 제출 현황, 공개 연출, 스킵
- 방장 전용 조작 (시작 / 강제 공개 / 스킵 / 다음 질문)
- 새로고침·탭 닫기 후 재접속

**제외 (의도적)**
- **지난 라운드 다시 보기** — 백엔드에 라운드 목록 엔드포인트가 없다. 만들려면 백엔드부터 늘려야 해서 v1에서 뺀다.
- **기기를 옮긴 뒤의 재접속** — 아래 "재접속" 참조. 보안상 못 한다.
- 계정·로그인 — 닉네임과 토큰이 전부다.
- 다국어 — 한국어만.

## 기술 선택

| | |
|---|---|
| 프레임워크 | Next.js (App Router) |
| 스타일 | Tailwind CSS |
| 애니메이션 | Framer Motion |
| 서버 상태 | TanStack Query |
| 테스트 | Vitest + Testing Library |

**Next.js 를 쓰는 이유는 서버 렌더링이 아니다.** 이 앱은 모든 호출이 localStorage 의 토큰을 필요로 해서 서버에서 미리 가져올 데이터가 없다. 사실상 SPA다. 그럼에도 Next 를 고르는 건 초대 링크(`/join/K3P9XM`) 딥링크가 설정 없이 동작하고 Vercel 배포가 `git push` 하나로 끝나기 때문이다. 모든 컴포넌트는 클라이언트 컴포넌트다.

**TanStack Query 를 쓰는 이유**는 폴링에 필요한 것 — 주기적 재조회, 탭이 숨겨지면 정지(휴대폰 배터리), 실패 시 백오프, 중복 요청 제거 — 이 이미 다 들어있어서다. 직접 만들 이유가 없다.

**Playwright 는 넣지 않는다.** 백엔드에 전체 흐름 e2e 가 이미 있어서 같은 것을 두 번 검증하게 된다.

## 화면

라우트는 셋이다.

### `/` 시작

닉네임을 받아 방을 만들거나, 6자리 코드로 기존 방에 참가한다.

방 코드 알파벳은 `ABCDEFGHJKLMNPQRSTUVWXYZ23456789` — `0/O/1/I` 가 빠져 있다. 입력은 대문자로 자동 변환하고, 6자가 차면 바로 검증한다.

### `/join/[code]` 초대 링크

친구가 공유 링크를 열면 코드는 채워져 있고 닉네임만 받는다. 이미 그 방에 세션이 있으면 곧바로 `/room/[code]` 로 보낸다.

중복 닉네임이면 백엔드가 409를 준다. 그 메시지를 그대로 보여주고 다시 입력받는다.

### `/room/[code]` 게임 화면

이 앱의 거의 전부. 라운드 상태에 따라 안에서 모습이 바뀐다.

| 상태 | 화면 |
|---|---|
| 라운드 없음 | 참가자 목록, 링크 복사 버튼, 방장에게만 "시작하기" |
| `open` · 내가 미제출 | 질문, 입력창, "N명 중 M명 제출" |
| `open` · 내가 제출함 | 내 답변, 참가자별 제출 여부 실시간, 방장에게 "그냥 공개" / "이 질문 넘기기" |
| `revealed` | 공개 연출 → 전체 답변, 방장에게 "다음 질문" |
| `skipped` | 질문과 "넘어갔습니다". **답변은 표시하지 않는다** |

`skipped` 에서 답변을 감추는 건 UI 취향이 아니다. 스킵된 라운드는 공개된 적이 없고, 백엔드도 그 응답에 답변을 담지 않는다(`RoundSkippedResponseDto`).

## 데이터 흐름

### 폴링 전환

한 번에 하나의 엔드포인트만 폴링한다. 주기는 2초.

```
라운드 없음                → GET /rooms/:code
라운드 open                → GET /rounds/:id
라운드 revealed / skipped  → GET /rooms/:code
```

세 번째 줄이 중요하다. 공개된 라운드는 더 이상 변하지 않으므로 계속 폴링하면 **방장이 다음 라운드를 시작한 것을 영영 감지하지 못한다.** 공개 이후에는 방 폴링으로 되돌아가 새 `currentRound.id` 를 기다린다.

라운드가 `open` 인 동안 참가자 목록과 제출 여부는 `GET /rounds/:id` 응답에 함께 오므로, 방 폴링을 동시에 돌릴 이유가 없다.

### API 응답 (백엔드 확정분)

```jsonc
// POST /rooms            201
{ "code": "K3P9XM", "participantToken": "…", "participantId": "1", "isHost": true }

// POST /rooms/:code/participants   201
{ "participantToken": "…", "participantId": "2", "isHost": false }

// GET /rooms/:code       200
{
  "code": "K3P9XM", "status": "waiting", "isHost": true,
  "participants": [{ "id": "1", "nickname": "지훈", "isHost": true }],
  "currentRound": { "id": "10", "sequence": 3, "status": "open" }   // 없으면 null
}

// POST /rooms/:code/rounds        201  (방장만)
{ "roundId": "11", "sequence": 4, "question": { "id": "42", "text": "…" } }

// GET /rounds/:id        200  — status 에 따라 세 모양
{ "roundId": "11", "status": "open", "question": {…},
  "participants": [{ "id": "2", "nickname": "민수", "submitted": false }],
  "mySubmission": { "text": "…" } }        // 미제출이면 null

{ "roundId": "11", "status": "revealed", "question": {…},
  "revealedAt": "2026-09-09T12:34:56.000Z",
  "revealedBy": { "id": "1", "nickname": "지훈", "isHost": true },  // 자동 공개면 null
  "answers": [{ "participantId": "1", "nickname": "지훈", "text": "…" }],
  "notSubmitted": [] }                      // 강제 공개 시에만 채워짐

{ "roundId": "11", "status": "skipped", "question": {…} }

// POST /rounds/:id/answers        201
{ "submitted": true, "allSubmitted": false }

// POST /rounds/:id/reveal         200  (방장만)   → revealed 응답
// POST /rounds/:id/skip           200  (방장만)   → { "roundId": "11", "status": "skipped" }
```

인증은 모든 요청의 `X-Participant-Token` 헤더.

## 공개 연출

이 앱에서 유일하게 까다로운 부분이다.

### 문제

백엔드는 2초 폴링 전제로 설계돼 있다. 각 클라이언트가 공개를 감지하는 시점이 최대 2초까지 어긋나므로, 감지 시점에 연출을 시작하면 **같이 있는 친구들끼리 다른 시각에 답을 보게 된다.** 다 같이 보는 게 이 게임의 핵심인데 그게 깨진다.

### 해법

백엔드가 이미 `revealedAt` 을 응답에 준다. 모든 클라이언트가 그 시각을 기준점으로 삼아 타이밍을 계산하면, 폴링이 언제 도착했든 카드가 열리는 벽시계 시각이 같아진다. 백엔드 수정이 필요 없다.

```
T0 = revealedAt
카드 i 가 열리는 시각 = T0 + STAGGER * i        (STAGGER = 700ms)

폴링이 T_now 에 도착했을 때 카드 i 는:
  T_now >= T0 + STAGGER*i  →  이미 열린 상태로 즉시 렌더 (애니메이션 없음)
  아니면                    →  (T0 + STAGGER*i) - T_now 뒤에 열림
```

늦게 받은 사람은 앞부분이 이미 펼쳐진 채로 시작해 남은 카드를 다른 사람과 같은 순간에 본다.

이 계산은 순수 함수로 분리한다. `(revealedAt, now, answerCount) → { index, delayMs }[]`. 프론트에서 단위 테스트할 가치가 있는 유일한 로직이다.

### 카드 순서

서버는 `answers` 를 제출 시각순으로 준다. 그대로 쓰면 **제일 빨리 낸 사람이 항상 1번**이라 몇 판 하면 예측 가능해진다. `roundId` 를 시드로 한 결정적 셔플을 적용해 모든 클라이언트가 같은 순서를 보되 제출 순서와는 무관하게 만든다.

### 예외

- `revealedAt` 이 `null` 이면 (DTO 상 nullable) 연출 없이 전체를 즉시 표시한다.
- `notSubmitted` 가 비어 있지 않으면 강제 공개다. 카드를 다 연 뒤 "○○님은 끝내 안 냈어요" 를 따로 보여준다.
- 사용자의 기기 시계가 서버와 크게 어긋나 `T0` 가 미래로 계산되면, 전체를 즉시 표시한다. 음수 지연으로 연출이 멈추는 것보다 낫다.

## 재접속

`quiz-app:session:<방코드>` 키에 `{ participantToken, participantId, nickname }` 를 저장한다. 방 코드로 키를 나누면 여러 방을 오가도 서로 덮어쓰지 않는다.

- `/room/[code]` 진입 시 세션이 없으면 `/join/[code]` 로 보낸다.
- 어떤 요청이든 401 이 오면 그 키를 지우고 `/join/[code]` 로 보낸다.
- 저장된 JSON 이 깨져 있으면 없는 것으로 취급하고 지운다.

**기기를 옮긴 경우는 살릴 수 없다.** 닉네임만으로 재입장시키는 엔드포인트를 만들면, 같은 방의 누구든 남의 닉네임을 대고 그 사람의 토큰을 받아 **공개 전에 그 사람의 답변을 볼 수 있다.** 이 앱이 지키려는 단 하나가 깨진다. 새 닉네임으로 다시 들어가는 것으로 둔다.

## 에러 처리

| 상태 | 처리 |
|---|---|
| 401 | 해당 방 세션 삭제 → `/join/[code]` |
| 403 | "이 방 참가자가 아니에요" |
| 404 | "방을 찾을 수 없어요" |
| 409 | **백엔드 메시지를 그대로 표시.** 중복 닉네임·중복 제출·라운드 종료·질문 소진이 모두 409인데 백엔드가 한국어로 구분해 준다 |
| 5xx · 네트워크 | 화면을 비우지 않고 마지막 데이터를 유지, 구석에 "연결 중" 표시. TanStack Query 백오프에 맡긴다 |

폴링 실패로 화면이 비는 일은 없어야 한다. 게임 중에 잠깐 끊겼다고 답변 작성 중이던 화면이 날아가면 최악이다.

## 백엔드 변경 (선행 조건)

프론트를 붙이기 전에 반드시 필요하다. 현재 배포된 백엔드는 **어떤 게임 요청도 처리하지 못한다.**

### 1. 운영 DB 에 마이그레이션이 돌지 않는다

`POST /rooms` 가 500 을 반환한다. Railway 로그의 Postgres 오류 코드는 `42P01`(테이블 없음). `start` 스크립트가 `npm run build && node dist/main` 뿐이라 마이그레이션 단계가 없다. 코드는 배포됐는데 테이블이 없는 상태다.

배포 시 마이그레이션이 실행되도록 start 경로에 `migration:run` 을 넣는다.

### 2. `CORS_ORIGINS` 미설정

`main.ts` 는 `CORS_ORIGINS` 를 읽고, 없으면 전체 허용으로 동작한다. Railway 환경변수에 Vercel 도메인을 지정한다.

## 미결 / 이후

- **참가자 탈퇴·강퇴 기능을 넣게 되면**, 자동 공개의 분모를 라운드 시작 시점으로 스냅샷해야 한다. 지금은 매 제출마다 현재 인원을 다시 세므로, 사람이 빠지면 분모가 줄어 **아직 안 낸 사람이 있는데 공개되는** 상황이 생긴다. 이 앱에서 가장 치명적인 버그가 된다.
- 지난 라운드 보기 — 백엔드에 라운드 목록 엔드포인트가 필요하다.
- 방장이 한 장씩 넘기는 공개 방식 — 반응을 보고 판단한다. 공개 진행 상태를 서버에 둬야 한다.
